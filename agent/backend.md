# Backend modules

Each entry gives the file, its job, its main exports, and who calls it. Line numbers are in `symbols.md`, which is generated.

## http/
- `http/server.ts`: the entry point, run as `dist/backend/http/server.js`. Before it listens it runs `importLegacyPiAuth()`; after it listens it runs `startMcpServers()`. It binds `HOST`:`PORT`. Each request is tried in this order: a `GET` whose path does not start with `/api/` goes to `serveStatic`; `POST /mcp` goes to `handleMcp`; `GET /api/mcp/oauth/callback` (`OAUTH_CALLBACK_PATH`) goes to `handleOAuthCallback`; `GET /api/slack/oauth/callback` (`SLACK_CALLBACK_PATH`) goes to `handleSlackCallback`; then `matchRoute` over `routes`; no match is `notFound()`. A thrown `AppError` answers its status, anything else answers 500, both as `{error}`. Callers: none. `app/system.ts` `restartMip` starts `dist/backend/http/server.js` again.
- `http/router.ts`: exports `Route`, `RouteContext` (`req`, `url`, `params`), `Handler`, the builders `get`, `post`, `put`, `patch`, `del`, and `matchRoute(routes, method, pathname)`. A `:name` segment captures one segment into `params`. Empty segments are dropped, so a trailing slash is ignored. Segments are `decodeURIComponent`-ed before they are compared, so an encoded `/` stays inside one segment. A malformed escape throws `URIError`, which `http/server.ts` answers with 500. The first route with the same method, the same segment count, and matching literal segments wins. Callers: `http/server.ts` (`matchRoute`) and every `http/routes/*.ts` (builders).
- `http/respond.ts`: exports `Reply` (`{status, body}`), `ok` (200), `created` (201), `accepted` (202), `ack` (200 `{ok: true}`), `notFound` (404 `{error: "not found"}`), `sendJson` (adds `Cache-Control: no-store`), `readJson`, and `requireJson`. `readJson` returns `{}` for an empty body, throws a `SyntaxError` for invalid JSON (answered 500 by `http/server.ts`), and does not check `Content-Type`. `requireJson` throws `AppError` 415 `send this request as JSON` unless `Content-Type` includes `application/json`. `http/server.ts` calls it for every `POST`, `PUT`, and `PATCH` to the API before routing, so no route calls it. Callers: `http/server.ts`.
- `http/mcp.ts`: exports `handleMcp(req, res, message)`. The tool endpoint for the Claude CLI: JSON-RPC 2.0 over HTTP. The bearer token in `Authorization` picks the run through `runContextForToken` (`app/tools/index.ts`). No run gives 401 `{error: "unauthorized"}`, including for notifications. A message with no `id` is a notification and gets 202 with no body. Methods: `initialize` (echoes `params.protocolVersion`, default `2025-03-26`; `serverInfo` `mip` `0.1.0`; `capabilities.tools`); `tools/list` (the run's `tools` as name, description, inputSchema; deferred tools are not listed, they are reached through `tool_search` and `tool_call`); `tools/call` (runs one of the run's `tools` with the run's workspace, agent, bot, room, and deferred list). An unknown tool is error `-32602`, an unknown method `-32601`; both are sent with HTTP 200. An exception thrown by `tool.run` is not caught here, so `http/server.ts` answers 500. Callers: `http/server.ts` (`POST /mcp`).
- `http/mcp-oauth.ts`: exports `handleOAuthCallback(url, res)`. The page the browser lands on at `OAUTH_CALLBACK_PATH`. A refusal (`error_description` or `error`) or a missing `state` or `code` is 400. It calls `completeSignIn(state, code, iss)` in `app/mcp/manager.ts` and shows "Signed in" (200), or "Sign-in failed" with the `AppError` status (500 otherwise). Tested by `app/mcp/mcp-oauth.test.mjs`. Callers: `http/server.ts`.
- `http/slack-oauth.ts`: exports `handleSlackCallback(url, res)`. The page the browser lands on at `SLACK_CALLBACK_PATH`. Same shape as `http/mcp-oauth.ts`: a refusal or a missing `state` or `code` is 400; it calls `completeConnect(state, code)` in `app/slack/connect.ts` and shows "Connected" (200) or "Connection failed". Callers: `http/server.ts`.
- `http/page.ts`: exports `page(res, status, title, message)`. Writes a small HTML page with `Cache-Control: no-store`. The title and message are escaped (`&<>"'` become numeric entities). Callers: `http/mcp-oauth.ts`, `http/slack-oauth.ts`.
- `http/static.ts`: exports `serveStatic(pathname, res)`. Serves files from `dist/frontend`, found relative to the compiled file. `/` is `index.html`. Content types: `.html`, `.js`, `.css`, `.svg`, `.png`, `.ico`; anything else is `application/octet-stream`. `Cache-Control: no-store`. A path that resolves outside the folder, or a missing file, returns false. Callers: `http/server.ts`.
- `http/routes/index.ts`: exports `routes: Route[]`, the domain lists concatenated in this order: `providerRoutes`, `agentRoutes`, `runRoutes`, `personaRoutes`, `botRoutes`, `roomRoutes`, `repoRoutes`, `memoryRoutes`, `syncRoutes`, `skillRoutes`, `toolRoutes`, `mcpServerRoutes`, `mailRoutes`, `slackRoutes`, `spendingRoutes`, `systemRoutes`. A new domain file is added here. Callers: `http/server.ts`.

Each route file exports one `Route[]`. The full table, with statuses, bodies, and errors, is in `api.md`. The paths below are the routes the file defines.

- `http/routes/agents.ts`: exports `agentRoutes`. Agents: list, create, open, settings, delete. Paths: `GET /api/agents`, `POST /api/agents`, `GET /api/agents/:agentId`, `PATCH /api/agents/:agentId`, `DELETE /api/agents/:agentId`. Calls `app/agents.ts`.
- `http/routes/runs.ts`: exports `runRoutes`. Starts a run and reads its events. Paths: `POST /api/run`, `GET /api/runs/:runId/events` (`?after=` is the last sequence seen). Calls `app/runs.ts`.
- `http/routes/personas.ts`: exports `personaRoutes`. Personas: list, create, edit, delete, make default. Paths: `GET /api/personas`, `POST /api/personas`, `PUT /api/personas/:personaId`, `DELETE /api/personas/:personaId`, `POST /api/personas/:personaId/default`. Calls `app/personas.ts`.
- `http/routes/bots.ts`: exports `botRoutes`. Bots: list, create, edit, delete. Paths: `GET /api/bots`, `POST /api/bots`, `PUT /api/bots/:botId`, `DELETE /api/bots/:botId`. Calls `app/bots.ts`.
- `http/routes/room.ts`: exports `roomRoutes`. Rooms and their messages. Paths: `GET /api/rooms`, `POST /api/rooms`, `PUT /api/rooms/:roomId`, `DELETE /api/rooms/:roomId`, `GET /api/room` (`?room=` and `?after=`), `POST /api/room/messages`. Calls `app/room/rooms.ts` and `app/room/room.ts`. Note the singular `/api/room` (messages) and plural `/api/rooms` (rooms).
- `http/routes/repos.ts`: exports `repoRoutes`. Repository clones: list, add by link, pull all, remove, copy into an agent. Paths: `GET /api/repos`, `POST /api/repos`, `POST /api/repos/pull`, `DELETE /api/repos/:repoId`, `POST /api/repos/:repoId/copies`. Calls `app/repos.ts`.
- `http/routes/memory.ts`: exports `memoryRoutes`. Shared notes and the memory graph. Paths: `GET /api/graph`, `GET /api/memory` (`?q=` searches), `POST /api/memory`, `GET /api/memory/:title`, `DELETE /api/memory/:title`. Calls `app/memory.ts`.
- `http/routes/providers.ts`: exports `providerRoutes`. Providers, their sign-in targets, and sign-in actions. Paths: `GET /api/providers`, `POST /api/providers/:providerId/targets/:targetId/:action` (`action` is `sign-in`, `answer`, or `sign-out`; any other value is 404). Calls `app/providers.ts`.
- `http/routes/system.ts`: exports `systemRoutes`. Paths: `POST /api/system/update` (`git pull --ff-only`), `POST /api/system/restart`. Calls `app/system.ts`.
- `http/routes/sync.ts`: exports `syncRoutes`. GitHub sync. Paths: `GET /api/sync`, `PUT /api/sync/account`, `POST /api/sync/run`. Calls `app/sync/engine.ts`.
- `http/routes/skills.ts`: exports `skillRoutes`. Installed skills, removal, creation, and the two-step import. Paths: `GET /api/skills`, `POST /api/skills`, `GET /api/skills/:name`, `DELETE /api/skills/:name`, `POST /api/skills/imports`, `POST /api/skills/imports/:importId/confirm`, `DELETE /api/skills/imports/:importId`. Calls `app/skills/registry.ts`, `app/skills/imports.ts`, `app/skills/create.ts`.
- `http/routes/tools.ts`: exports `toolRoutes`. The tool registry, read only. Path: `GET /api/tools` (`describeTools`). Calls `app/tools/index.ts`.
- `http/routes/mcp-servers.ts`: exports `mcpServerRoutes`. MCP server state, add, remove, reload, sign-in. Paths: `GET /api/mcp`, `POST /api/mcp`, `POST /api/mcp/reload`, `DELETE /api/mcp/:name`, `POST /api/mcp/:name/sign-in`. Calls `app/mcp/manager.ts` and `app/mcp/servers.ts`.
- `http/routes/mail.ts`: exports `mailRoutes`. Mail accounts, their test, and reading messages. Paths: `GET /api/mail/accounts`, `POST /api/mail/accounts`, `DELETE /api/mail/accounts/:id`, `POST /api/mail/accounts/:id/test`, `GET /api/mail/accounts/:id/messages` (`?count=`, clamped to 1 to 200), `GET /api/mail/accounts/:id/messages/:uid`. Calls `app/mail/mail.ts`.
- `http/routes/slack.ts`: exports `slackRoutes`. The Slack app, connecting and disconnecting accounts, reading and posting as a connected user. Paths: `GET /api/slack`, `PUT /api/slack/app`, `POST /api/slack/connect`, `POST /api/slack/token`, `DELETE /api/slack/accounts/:id`, `GET /api/slack/accounts/:id/conversations`, `GET /api/slack/accounts/:id/unread`, `GET /api/slack/accounts/:id/conversations/:channel/messages`, `GET /api/slack/accounts/:id/conversations/:channel/threads/:ts`, `POST /api/slack/accounts/:id/conversations/:channel/messages`. The `GET` reads take `?refresh=1` to skip the cache. Calls `app/slack/slack.ts`, `app/slack/connect.ts`, `app/slack/read.ts`, `app/slack/post.ts`.
- `http/routes/spending.ts`: exports `spendingRoutes`. Spending entries. Paths: `GET /api/spending`, `POST /api/spending` (201). Calls `app/spending.ts`.

## app/: use cases
- `app/config.ts`: `HOST` (always `127.0.0.1`) and `PORT` (`MIP_PORT`, default 3000). Callers: `app/runs.ts` and `app/room/room.ts` (the tool endpoint `http://HOST:PORT/mcp`), `app/mcp/manager.ts` and `app/slack/connect.ts` (OAuth redirect addresses), `http/server.ts`.
- `app/errors.ts`: `AppError(status, message)`, the error for a client mistake, and `errorMessage(err)`. Callers: most `app/` modules, and `http/server.ts`, `http/respond.ts`, `http/mcp-oauth.ts`, `http/slack-oauth.ts`.
- `app/git.ts`: `runGit(args, env?)`. Runs `git` with `GIT_TERMINAL_PROMPT=0`, so a clone that needs a password fails instead of waiting. Resolves with trimmed stdout. Rejects with the first `fatal:` or `error:` line of stderr. `env` adds variables for that call only. Callers: `app/repos.ts`, `app/system.ts`, `app/sync/repo.ts`.
- `app/names.ts`: `pickAgentName(taken: Set<string>)`. A random Norse name from the groups in the file that is not in `taken`. When every name is taken, a random name gets ` 2`, ` 3`, and so on. Caller: `app/agents.ts` (`createAgent`, with the titles of all agents).
- `app/system.ts`: `pullLatest()` runs `git -C <checkout root> pull --ff-only` and returns its output. `restartMip()` starts a detached `sh` that waits for this process to exit, runs `npm install` and `npm run build` (output appended to `MIP_HOME/restart.log`), then runs `dist/backend/http/server.js` with the same node binary. The server starts even when install or build fails. This process exits 300 ms after the call. Caller: `http/routes/system.ts`.
- `app/installation.ts`: `installationId()`. This installation's device ID: a UUID kept in `DEVICE_ID_FILE` (`MIP_HOME/data/device-id`), made on first use. A saved value that is not a UUID is replaced. It is not synced. Caller: `app/providers.ts`, which gives it to `PiProvider`; Pi passes it to each sign-in. Tested by `app/installation.test.mjs`.
- `app/agents.ts`: exports `allAgents()`, `createAgent(providerId, personaId?)`, `getAgentDetail(id)` (`{agent, messages, activeRunId}`), `updateAgent(id, changes)`, `removeAgent(id)`. Create gives an unknown provider or persona 400, and a new agent a name from `pickAgentName`. `updateAgent` takes `title` (non-empty), `openToBots` (boolean), `model`, and `thinking`. The model must be in `findProvider(id).models()`, and the thinking level must be in that model's `thinkingLevels`. An empty model or thinking means the provider default. If the request does not set `thinking`, a level the new model lacks is cleared; if it does set one, that level is a 400. `removeAgent` answers 409 while a run is active, then deletes the messages and the workspace (`removeWorkspace`). The persona is fixed for the agent's life. Missing agent: 404 `no such agent`. Caller: `http/routes/agents.ts`.
- `app/runs.ts`: exports `startRun({agentId, prompt, onFinish?})` (returns the run id; 404 unknown agent, 400 empty prompt, 409 agent already running), `readRun(runId, after)` (`{status, events}`; 404), `activeRunId(agentId)`, and the type `RunReply` (`{text, error}`). `startRun` saves the user message, registers a run token for `AGENT_TOOLS` and `agentDeferredTools()`, and starts `execute` in the background. `execute` builds the system prompt from `personaPrompt`, `repoNote(workspace)`, `toolGuidesPrompt(AGENT_TOOLS)`, and `recallFor(prompt)`. It passes the agent's model, thinking level, and `providerSessionId`, and the tool endpoint `http://HOST:PORT/mcp` with the token. Each provider event is saved as it arrives, with a sequence number. At the end it releases the token, saves the reply with its tool calls and any pending `ask_user` question (`takePendingAsk`), saves the provider session id, sets the run to `done` or `error`, and calls `onFinish`. Callers: `http/routes/runs.ts` (`startRun`, `readRun`), `app/agents.ts` (`activeRunId`), `app/tools/index.ts` (`startRun`, `activeRunId`). This file and `app/tools/index.ts` import each other; `app/tools/index.ts` imports `startRun` for its `agent_ask` tool. If saving the reply throws, the run stays `running` until restart, when `storage/db.ts` sets leftover running runs to `error`; the agent is busy until then. The prompt is saved as typed; a leading `/name` is expanded only for the provider (`withSkillCommand`).
- `app/personas.ts`: exports `DEFAULT_PERSONA_ID` (`"default"`), `allPersonas()`, `defaultPersona()`, `hasPersona(id)`, `personaPrompt(id)` (the prompt text; the built-in one when the persona is missing), `createPersona(name, systemPrompt)`, `editPersona(id, name, systemPrompt)`, `makeDefaultPersona(id)`, and `removePersona(id)`. Loading the module writes to the database: it inserts the built-in persona `default` if missing, makes one persona the default if none is, and replaces the built-in text only when the stored text hashes to `PREVIOUS_DEFAULT_HASH` (an unedited older copy). The built-in prompt (`DEFAULT_SYSTEM_PROMPT`, not exported) covers identity, working style, and answer style. Delete answers 400 for the built-in persona and for the current default, 409 with the count of agents that use it, and 404 for an unknown id. Callers: `http/routes/personas.ts`, `app/agents.ts` (`defaultPersona`, `hasPersona`), `app/runs.ts` (`personaPrompt`), `app/tools/guides.test.mjs` (`defaultPersona`).
- `app/bots.ts`: exports `allBots()`, `createBot(input)`, `editBot(id, input)`, `removeBot(id)`, and `nextBotColor(used)`. The checks in the private `checkFields`: the name matches `^[A-Za-z][A-Za-z0-9_-]{1,23}$` and is unique ignoring case (the `bots.name` column is `COLLATE NOCASE`), a clash is 409; `persona` is required, at most 4000 characters; `providerId` defaults to `claude-cli` and must exist; `model` and `thinking` must be in the provider's live `models()` list, and a thinking level the model lacks is 400 (unlike agents, it is not cleared); `color` must be in `BOT_COLORS` (`storage/bot-colors.ts`). On create without a color, `nextBotColor` gives the first color no bot uses, and repeats in `BOT_COLORS` order once all are used. On edit without a color, the bot keeps its color. Unknown bot: 404. Callers: `http/routes/bots.ts`, `app/bots.test.mjs` (`nextBotColor`), `app/room/rooms.test.mjs` (`removeBot`).
- `app/providers.ts`: exports `reloadPiConfig()`, `hasProvider(id)`, `findProvider(id)` (404 `unknown provider "<id>"`), `listProviders()`, `signIn(providerId, targetId, method)`, `answerSignIn(providerId, targetId, answer)`, and `signOut(providerId, targetId)`. The module makes the two providers: `ClaudeCliProvider` (`id` `claude-cli`, config under `SESSIONS_DIR/claude`) and `PiProvider` (`id` `pi`, sessions under `SESSIONS_DIR/pi`, credentials and model catalogs in the database through `app/pi/store.ts`). `listProviders` returns each provider's models, sign-in targets, and sign-in progress. A provider whose targets fail is listed with `targets: []` and an `error`. `signIn`, `answerSignIn`, and `signOut` do nothing for a provider that lacks the optional method, and the route still answers 202 for sign-in. Callers: `http/routes/providers.ts` (`listProviders`, `signIn`, `answerSignIn`, `signOut`), `app/agents.ts` and `app/bots.ts` (`hasProvider`, `findProvider`), `app/runs.ts` and `app/room/room.ts` (`findProvider`), `app/sync/engine.ts` (`reloadPiConfig`).
- `app/memory.ts`: exports `writeNote(title, body)` (creates the note, or replaces the one with the same title ignoring case; returns `{title, links, tags}`), `readNote(title)` (the note with `links`, `backlinks`, and `tags`), `searchMemory(query, limit, minLength = 2)`, `memoryList(query)` (a search of any word when `query` is set, up to 100 notes; otherwise every note), `memoryGraph()` (`{nodes, edges}`: a node per note, a node with `missing: true` per linked title that has no note, and undirected edges), and `forgetNote(title)` (404). `recallFor(prompt)` gives text for the system prompt: up to 5 notes that match words of 4 or more characters, or the empty string. Links are `[[Title]]` or `[[Title|alias]]`; tags are `#tag`. Callers: `http/routes/memory.ts`, `app/tools/memory.ts` (`writeNote`, `readNote`, `searchMemory`), `app/runs.ts` (`recallFor`).
- `app/repos.ts`: exports `listRepoCards()` (each repository with its `branch` and the agents that hold a copy), `pullAllRepos()` (`git pull --ff-only` on each ready master clone; one `{id, name, ok, message}` per repository; agents' copies are not pulled), `addRepo(url)` (validates the link and starts `git clone` into `REPOS_DIR` in the background; the repository shows `cloning`, then `ready`, or `error` with the partial folder removed), `copyRepoToAgent(repoId, agentId)` (a separate clone in the agent's workspace whose `origin` is the real link), `removeRepo(repoId)`, and `repoNote(workspace)` (text naming the repositories in a workspace, or empty). Links: `http`, `https`, `ssh`, `git`, or `file` URLs, or `user@host:path`; a bare `host/path` gets `https://`. The folder name is the last path segment without `.git`. Errors: 400 for a bad link or folder name; 409 for a name already taken, a repository still cloning, a repository not ready, or an agent that already has a copy; 404 for an unknown repository or agent. Callers: `http/routes/repos.ts`, `app/runs.ts` (`repoNote`).
- `app/spending.ts`: exports `allSpending()` (newest first) and `saveSpendingEntry(input)`. Fields: `kind` (`income` or `expense`); `category` (required, at most 40 characters; a case-insensitive match to an existing category uses that spelling); `amount` (a number above 0); `description` (optional, trimmed, at most 200 characters); `id` (optional, at most 64 characters). With an `id`, the entry replaces that one and keeps its `createdAt`; without one, a UUID is made. Each refusal is a 400 with its message. Callers: `http/routes/spending.ts`, `app/tools/financial.ts` (`allSpending`, `saveSpendingEntry`).

Tests: `app/bots.test.mjs`, `app/installation.test.mjs`, `app/spending.test.mjs`. Each imports `dist/backend`, so run `npm run build:backend` first, then `node <file>`.

## app/room/: the bots room
- `app/room/room.ts`: exports `postToRoom(input)`, `roomMessages(roomId, afterId)`, and `roomStatus(roomId)`. `postToRoom({room, text})` saves the message with author `You`, starts the conversation in the background, and returns the saved message. Errors: 404 unknown room, 409 room busy (checked before the text), 400 empty or over 4000 characters. A room with no bots gets a system message and no turn runs. Speaking order: when the text names bots (`mentionedBots`, `@Name`), only those speak, in the order named. Otherwise the room master (`masterBotId`) speaks first, then the other members in `listBots()` order (name, ignoring case). `converseRoom` (from `app/room/engine.ts`) runs at most `MAX_TURNS` (8) turns. `runTurn` gives one bot a turn: the prompt is the last `HISTORY` (30) room messages as `Author: text`, plus instructions to reply `PASS` to stay silent and to mention `@Name` to hand over. The system prompt is `bot.persona`, the room rules (`You are in the room "<name>" with the user and other bots. Keep each message short.`), and `toolGuidesPrompt(BOT_TOOLS)`. The run token is `registerRun({tools: BOT_TOOLS, deferred: botDeferredTools(), botId, roomId})` with no workspace. No provider session id is passed, so each turn is a new provider session. A provider `error` event fails the turn, and the room posts `<name> couldn't reply: <message>`. `roomStatus(roomId)` returns `{busy, speaking}` from an in-memory map, so a restart clears it. `roomMessages` gives 404 for an unknown room; with `afterId` 0 it returns the latest 100 messages, otherwise up to 200 messages with a larger id, both oldest first. Callers: `http/routes/room.ts` (`postToRoom`, `roomMessages`, `roomStatus`), `app/room/rooms.test.mjs`.
- `app/room/rooms.ts`: exports `allRooms()`, `createRoom(input)`, `editRoom(id, input)`, and `removeRoom(id)`. Fields: `name` (required, trimmed, at most 40 characters, unique ignoring case with `COLLATE NOCASE`, a clash is 409); `botIds` (a list; each id must be an existing bot; duplicates are dropped; a bad entry is 400); `masterBotId` (null or a bot in `botIds`, else 400; when a change to `botIds` removes the master, the master is cleared without an error); `collapseOthers` (boolean, default false). On edit, a field left out keeps its value. `removeRoom` answers 404 for an unknown room and 409 for the last room; the room's messages are deleted with it. Callers: `http/routes/room.ts`, `app/room/rooms.test.mjs`.
- `app/room/engine.ts`: pure turn-taking, with no storage or provider code. Exports `RoomBot`, `RoomEvent` (`kind` `bot` or `system`), `ConverseOptions`, `mentionedBots(text, bots)` (`@Name` matches, ignoring case, in the order named, without repeats; unknown names are ignored), `isSilent(text)` (empty, or `PASS` ignoring case and spaces), and `converseRoom(options)`. The loop: each turn counts toward `maxTurns`, silent turns included, and calls `runTurn`. A silent reply is dropped. Any other reply goes to `say` with its calls, and the bots it names are queued unless already waiting. At the limit it says `Paused after <n> turns. Mention a bot to keep the room going.` and stops. A failing turn says `<name> couldn't reply: <message>` and stops. `speaking(name)` is called before each turn, and with `null` at the end. Callers: `app/room/room.ts`. Tested by `app/room/engine.test.mjs`.

## app/tools/: the tool registry
- Paths are relative to `src/backend/`. The call flow is in `flows.md`.
- Kinds (the `load` field of `describeTools`): `basic` is offered to the run, and its guide goes into the system prompt. `search` is `tool_search` and `tool_call`. `deferred` is not offered: `tool_search` returns its guide and inputs, and `tool_call` runs it.
- Run kinds: an `agent` may use `AGENT_TOOLS`, `AGENT_DEFERRED`, and `mcpTools()`. A `bot` may use `BOT_TOOLS` and `botDeferredTools()`. `tool_call` runs only a tool in the run's `deferred` list.
- `ToolSpec` (`adapters/contract.ts`): `name`, `description`, `guide` (one paragraph), `inputSchema` (JSON Schema), `run(input, context)` returning `ToolResult` (`{text, isError}`). `ok` and `fail` (`result.ts`) build results. `ToolContext`: `workspace`, `agentId?`, `botId?`, `roomId?`, `deferred?`, `signal?`.
- Every mip tool is wrapped once by `guarded` (`index.ts`): a throw becomes `{text: message, isError: true}`. MCP tools are not wrapped; `app/mcp/manager.ts` catches their errors.

Tool files (kind, run kinds, required inputs):
- `app/tools/index.ts`: the registry (lists below). Defines two tools that are not exported: `agents_list` (basic, bot; no required input) and `agent_ask` (basic, bot; required `agent`, `task`). `agents_list` lists the agents with `openToBots`, marking busy ones. `agent_ask` starts the agent's run with `startRun` (`app/runs.ts`); its `onFinish` posts the reply to the room as an `agent` message. One task per room at a time. They are defined here because `runs.ts` reads this registry. Tested by `agents.test.mjs`; `guides.test.mjs` checks every guide.
- `app/tools/ask.ts`: `askUserTool` (`ask_user`). Basic, agent. Required: `question`, `kind` (`choice`, `multi`, `text`, `slider`). Choice and multi take 2 to 8 `options`; a slider needs `min` below `max`. Exports `takePendingAsk(agentId)`, which `runs.ts` calls when the run ends. One question per run. Tested by `ask.test.mjs`.

## app/mcp/: external MCP servers
- Config file: `data/mcp.json` under `MIP_HOME` (`MCP_CONFIG_FILE`, `storage/paths.ts`). Shape: `{"mcpServers": {<name>: entry}}`. Every write is mode 600. Synced (see Sync below).
- Name rule: `^[A-Za-z0-9][A-Za-z0-9_-]{0,31}$`.
- Entry `type`: `"stdio"` or `"http"`. With no `type`, an entry with a string `url` is `http`, anything else is `stdio`. Any other type is refused.
- `stdio` entry: `command` (non-empty string), `args` (string list, optional), `env` (string map, optional).
- `http` entry: `url` (an `http:` or `https:` URL), `headers` (string map, optional), `oauth` (optional object: the sign-in state, see Sign-in below).
- A bad entry is reported as `{server, error}` in `problems` and skipped. The other entries still load.

Files:
- `app/mcp/config.ts`: `parseMcpConfig(text)` (pure, returns `{servers, problems}`), `readMcpConfig()` (no file means no servers), `mcpConfigText(entries)` (the file text, entries sorted by name, no other top-level key), `writeMcpConfigText(text)` (mode 600), `editMcpFile(change)` (edits the `mcpServers` map and keeps every other entry and top-level key). Types `McpServerConfig`, `McpServerEntry`, `McpConfigProblem`. `editMcpFile` throws `AppError` 409 when the file is not a JSON object or `mcpServers` is not an object. Callers: `manager.ts`, `servers.ts`, `app/sync/snapshot.ts`. Tested by `mcp.test.mjs`.
- `app/mcp/manager.ts`: the connections. Exports `startMcpServers()`, `closeMcpServers()`, `mcpTools()`, `mcpStatus()`, `mcpToolName(server, tool)`, `signInServer(name)`, `completeSignIn(state, code, iss?)`, and `OAUTH_CALLBACK_PATH` (`/api/mcp/oauth/callback`). Callers: `http/server.ts` (start at boot, and the callback path), `http/routes/mcp-servers.ts`, `http/mcp-oauth.ts` (`completeSignIn`), `app/tools/index.ts` (`mcpTools`), `app/sync/engine.ts` (`startMcpServers` after a sync changes the servers). Tested by `mcp.test.mjs` and `mcp-oauth.test.mjs`.
- `app/mcp/servers.ts`: `addMcpServer(input)` and `removeMcpServer(name)`. `addMcpServer` builds the entry from the form, checks it with `parseMcpConfig`, and writes it. `removeMcpServer` deletes it. Both then call `startMcpServers()` and return `mcpStatus()`. Form transports: `oauth` (a web server that signs in; the user gives only `url`), `http` (`url`, `headers`), `stdio` (`command`, `args`, `env`). A name already listed is 409; an entry the file would not load is 400. Callers: `http/routes/mcp-servers.ts`. Tested by `mcp-oauth.test.mjs`.

Connections (`manager.ts`):
- Every server connects in parallel at start (`Promise.all`). Start and list-tools each time out after 30 s (`CONNECT_TIMEOUT_MS`). One tool call times out after 120 s (`CALL_TIMEOUT_MS`).
- `status` values: `connecting`, `connected`, `error`, `sign-in`. `error` carries the failure text, with its cause. A connection that closes after it connected becomes `error` with "the connection closed", and its tools are dropped.
- `mcpTools()` returns the tools of `connected` servers only. Each `ToolSpec` has the `mcp_<server>_<tool>` name, a `description` ending in "(MCP server <server>, tool <tool>)", and a `guide` that is the server's tool description, or its title, or its name, in that order.
- Result text: text parts as they are, images as `[<mime> image]`, nothing as `(no output)`. `isError` is the server's flag.
- Name clash: a tool whose name is already taken is skipped and added to `problems`. The first server to finish connecting keeps the name, so the winner depends on timing.
- `startMcpServers()` closes every current connection first. A connection still starting when it is replaced is closed when its connect finishes.
- `mcpStatus()` returns `{configFile, servers: [{name, transport, status, error, oauth, signInUrl, tools: [{name, remoteName, description}]}], problems: [{server, error}]}`. It never includes tokens or environment values.

Sign-in (OAuth, an `http` entry with `oauth`):
- The `oauth` object is pi-mcp's sign-in state. On read, `serverUrl` is set to the entry's `url`, so a state never applies to another server. Tokens and the `oauthState` value are saved in that object in `data/mcp.json`. Every save from the OAuth provider writes it (`saveSignIn`), so refreshed tokens persist across restarts.
- The first connect without tokens leaves the server in `sign-in`, with `oauth: true` and `signInUrl` set to the authorization link.
- Redirect address: `http://127.0.0.1:<MIP_PORT, default 3000>/api/mcp/oauth/callback`. The client name is `mip`.
- `completeSignIn(state, code, iss?)` finds the `sign-in` connection with that state. No match: `AppError` 400 "This sign-in is no longer waiting. Start it again from the MCP card." `authorizeMcp` fails: status `error`, `AppError` 502 "The sign-in did not finish: ...". Success: status `connecting`, reconnect in the background, and the server's name is returned.
- `signInServer(name)`: `AppError` 404 for an unknown name, 400 for a server without `oauth`. Otherwise it closes the client and connects again, which makes a new `signInUrl`.
- Routes that call these: see `api.md` (`/api/mcp`, `/api/mcp/reload`, `/api/mcp/:name`, `/api/mcp/:name/sign-in`, `/api/mcp/oauth/callback`).

Sync:
- `app/sync/snapshot.ts` sends the servers as the `mcp` part, with their tokens and environment values, to the private dotmip repo's `mcp/` folder (`app/sync/repo.ts`).
- An `mcp.json` with a problem stops the sync with 409. Nothing is changed, because a server left out would be deleted on GitHub.
- When a sync changes the servers, `applyMcp` checks the new text with `parseMcpConfig` and writes it with `writeMcpConfigText`. Top-level keys other than `mcpServers` are dropped by that write.
- MCP servers have no change time. When both sides changed one server, GitHub's copy is kept (`merge.ts`, `mcpKind`).

## app/pi/: Pi's credentials and catalogs
- Storage, in the app database (`storage/db.ts`, `storage/pi.ts`): table `pi_credentials` (`provider_id` primary key, `credential` JSON text, `updated_at`); table `pi_models` (`provider_id`, `entry` JSON text, `updated_at`); table `pi_state` (`key`, `value`). Each row has its change time, which sync uses to keep the newer copy.
- Pi's files in `data/pi/` (`PI_AGENT_DIR`, Pi's agent folder): `settings.json` and `models.json` only (`PI_CONFIG_FILES`, `storage/pi.ts`). `app/pi/store.ts` reads no file except the legacy auth file below.
- Sync (`app/sync/repo.ts`): the dotmip repo folders `pi-credentials/` (keys and tokens, so the repo is private), `pi-models/`, and `pi-files/`.
- `app/pi/store.ts`:
  - `DbCredentialStore` implements pi-ai's `CredentialStore`. `read(providerId)`, `list()` (provider ID and type only), `modify(providerId, fn)`, and `delete(providerId)`. `modify` is the only path that writes a credential: `fn` gets the current credential and returns the new one, or `undefined` to leave it as it is. Tasks for one provider run one after another; a failed task does not stop the next.
  - `DbModelsStore` implements pi-ai's `ModelsStore`: `read`, `write`, `delete`. No ordering.
  - `importLegacyPiAuth(path = LEGACY_PI_AUTH)` returns the number of credentials copied. `LEGACY_PI_AUTH` is `~/.pi/agent/auth.json`.
  - Import rules: it runs only when `pi_state` has no `pi-auth-imported` key. It copies only when `pi_credentials` is empty and the file exists, and only entries whose `type` is `api_key` or `oauth`. It then writes `pi-auth-imported` with the ISO time, even when nothing was copied, so it never repeats. The file is never changed. A file that cannot be read or parsed throws before the key is written, so the next start tries again.
- Callers: `app/providers.ts` builds both stores and passes them to `PiProvider` (`adapters/pi.ts`), which uses them through `ModelRuntime`. `http/server.ts` calls `importLegacyPiAuth()` once at boot, before the first request, and logs the count when it is above 0.
- Sign-in itself runs in `adapters/pi.ts`. This folder stores the result only.
- Tested by `pi-store.test.mjs`.

## app/mail/: mail over IMAP
- `app/mail/accounts.ts`: the accounts file. Exports `MAIL_PRESETS` (ids `gmail`, `icloud`, `fastmail`, `outlook`, `other`), `MailAccount` (with `smtp: MailServer`, the server it sends through), `MailServer` (`host`, `port`, `secure`), `smtpFor(imapHost)` (the known providers' SMTP servers; any other host gets `smtp.` in place of `imap.` on port 465, encrypted), `MailAccountView` (no password), `MailAccountProblem`, `parseMailAccounts` (pure; a bad entry is reported by id and the others load), `readMailAccounts`, `viewOf`, `idFor`, `saveMailAccount` (409 if the id is listed), `removeMailAccount` (404 if not listed), `writeMailAccounts` (sync; checks every account first, and on a failure throws 409 and changes nothing). Callers: `mail.ts`, `snapshot.ts`, `tools/social.ts`.
- `app/mail/imap.ts`: IMAP reads on `imapflow`. Exports `LIST_LIMIT` (25), `signInOnce` (add: connect, count, log out), `checkAccount` (count on the saved connection), `syncMailbox(account, cached, count)` (headers only), `fetchMessage(account, uid)` (one parsed message), and `moveToTrash(account, uid)`, the only write: it searches for the UID first (`false` when absent), finds the folder marked `\Trash` (or named Trash, Deleted Items, Deleted Messages, or Bin), and moves the message there with `messageMove` on a read-write lock. A mailbox with no Trash folder is 409, and a refused move throws. Caller: `mail.ts`.
- `app/mail/smtp.ts`: sending on `nodemailer`. `sendThrough(account, mail)` builds a transport from `account.smtp` with the account's own login (20 s timeouts), sends from `account.user` with the `to`, `cc`, `subject`, and `text` it is given, closes the transport, and returns the Message-ID. Nothing is kept on the server, and the provider keeps any copy in Sent. Caller: `mail.ts`.
- `app/mail/sessions.ts`: the in-memory connection per account. Exports `inSession(account, work)`, `closeMailSession(id)`, `closeAllMailSessions`, `sessionCount`, `setIdleCloseMs`, `DEFAULT_IDLE_CLOSE_MS`, `newConnection`. Callers: `imap.ts`, `mail.ts`.
- `app/mail/cache.ts`: the header cache. Exports `readMailCache`, `saveMailbox(id, box)`, `dropMailbox(id)`, type `CachedMailbox`. Callers: `mail.ts`, `snapshot.ts`.
- `app/mail/messages.ts`: pure mapping from an `imapflow` message. Exports `headerOf`, `senderText`, `messageOf`, `clipBody`, `htmlToText`, types `MailHeader`, `MailMessage`. Callers: `imap.ts`, `mail.ts`.
- `app/mail/mail.ts`: the facade. Exports `mailAccountsReply`, `addMailAccount`, `deleteMailAccount`, `testMailAccount`, `listMailMessages`, `openMailMessage`, `sendMailMessage`, `trashMailMessage`, `reasonOf`. Callers: `http/routes/mail.ts` (`mailRoutes`; routes in `api.md`) and the bot tools in `tools/social.ts` (`mail_list` calls `listMailMessages`, `mail_read` calls `openMailMessage`, `mail_send` calls `sendMailMessage`, `mail_delete` calls `trashMailMessage`).
- Sending (`sendMailMessage(id, input)`): checks before the server is asked, each 400. At least one recipient in `to`, and each address in `to` and `cc` matches `^[^\s@,<>"]+@[^\s@,<>"]+\.[^\s@,<>"]+$`; 20 addresses at most across both. `subject` has its whitespace collapsed to single spaces, so a line break cannot start a header; it must be 1 to 300 characters. `text` is trimmed and must be 1 to 20,000 characters. A send failure is 502 `Could not send from <label>: <reason>`. Nothing is kept by mip; the provider keeps a copy in Sent.
- Deleting (`trashMailMessage(id, uid)`): a UID that is not a positive integer is 400; a UID the mailbox does not have is 404; a mailbox with no Trash is 409; a failure is 502 `Could not delete from <label>: <reason>`. On success the message is also taken out of the cached headers.
- Account SMTP: `smtp` in `mail.json` names the server to send through. An entry without it gets `smtpFor(host)`, so existing accounts send without a change to the file. The add form does not ask for it, so an `other` account sends through `smtp.` plus its IMAP host unless `mail.json` says otherwise.
- Config: `data/mail.json` (under `MIP_HOME`). Shape: `{"accounts": {"<id>": {label, host, port, secure, user, password, mailbox, watch: {mode, pollSeconds}, maxBytes, smtp: {host, port, secure}}}}`. Mode 600 on every write (`writeFileSync` with the mode, then `chmodSync`). Other top-level fields, and accounts that do not load, are kept on save.
  - Defaults: `label` is `user`, `port` 993, `secure` true, `mailbox` `INBOX`, `watch.mode` `auto`, `watch.pollSeconds` 60, `maxBytes` 20000. Required: `host`, `user`, `password`.
  - Limits: id matches `^[A-Za-z0-9][A-Za-z0-9_-]{0,31}$`; port 1 to 65535; `maxBytes` 1000 to 1000000; `pollSeconds` 1 to 86400, raised to 15 (`MIN_POLL_SECONDS`) when lower; `watch.mode` is `auto`, `idle`, or `interval`.
- Add (`addMailAccount`): `preset`, `address`, and `password` are required (400). Spaces are removed from the password. The same address on the same host is 409. The server signs in before anything is saved; a refusal is 400 `Could not sign in to <host>: <reason>`. The saved account has `label` = address, `mailbox` `INBOX`, `watch` `auto` with 60 s, `maxBytes` 20000. `idFor` makes the id from the address, with `-2`, `-3` appended on a clash.
- Errors: views never carry `password`. A failed read is 502 `Could not read <label>: <reason>`; the reason is the server's `responseText` or the error message. An unknown account or UID is 404; a UID that is not a positive integer is 400.
- Cache: `data/mail-cache.json`, `{"<accountId>": {uidValidity, messages}}`, headers only (`uid`, `from`, `subject`, `date`, `seen`), newest first. Created with mode 600 and not re-chmodded. An unreadable file reads as empty. A changed `uidValidity` empties that mailbox's cache.
- `listMailMessages(id, count?)`: `count` defaults to the larger of 25 and the cached length. `complete` is true when the mailbox has no older messages to show. Every call saves the mailbox back to the cache.
- Connections: one per account, in the map inside `sessions.ts` (memory only, never saved). A session is replaced when host, port, secure, user, or password changes (SHA-256 of those five). Reads on one account run one at a time. A connection the server dropped is replaced; a read that fails on an open connection runs once more on a new one; a read that fails on a new connection throws. A connection with no read for 5 minutes (`DEFAULT_IDLE_CLOSE_MS`) is closed after the queued reads finish.
- IMAP behavior: the mailbox is opened with a read-only lock, except in `moveToTrash`, the one write. A body is fetched with `BODY.PEEK` (imapflow's source fetch), so reading never sets `\Seen`. IDLE is off (`disableAutoIdle`). The card re-reads each account every `watch.pollSeconds` (`src/frontend/features/email/useMail.ts`).
- Sync: carried as `mail/<id>.json` (with the app password) and `mail-cache/<id>.json`. Neither has a change time. When both sides changed an account, GitHub's copy wins and the sync log says so; an edit on one side and a delete on the other keep the edit. The cache takes GitHub's copy with no log entry. A problem in `mail.json` (or invalid JSON) stops the sync with 409 (`readMailForSync` in `snapshot.ts`).
- Gotcha: a sync that removes an account does not call `closeMailSession`. Its connection closes on the idle timer.
- Absent from the code: IDLE (`watch.mode` is validated and stored, and nothing reads it) and a watcher for new mail. Sending and moving to Trash exist, but only the bot tools `mail_send` and `mail_delete` call them; no card or route does.
- Tests (run after a build): `accounts.test.mjs` (defaults, bad entries reported by id, ids, saves keep unknown fields, mode 600, views without password, removal, sync checks, the SMTP server); `messages.test.mjs` (header from envelope and flags, date, read state, cut body, HTML without text); `mail.test.mjs` (wrong password refused and nothing saved, reads share one connection, bodies peeked, 404 and 400, dropped and idle connections, 502 without the password, removal closes the connection); `mail-sync.test.mjs` (a reload reads only new headers, Load more reads only older ones, removed messages leave the list); `mail-write.test.mjs` (the SMTP server from the IMAP host, a message sent with its login and the subject's line breaks made spaces, refusals before sending, a refused login without the password, a move to Trash that leaves the list and is 404 for a missing UID, 409 with no Trash folder). `fake-imap.test-support.mjs` (with `MOVE`, a Trash folder, and `SEARCH` by UID) and `fake-smtp.test-support.mjs` (AUTH PLAIN, no encryption) are the fake servers these tests use.

## app/sync/: GitHub sync
- `app/sync/engine.ts`: the sync runs. Exports `syncStatus`, `chooseAccount(login)`, `startSync`, `syncWith({url, env, repo})` (one sync; the tests call it), types `SyncRun`, `SyncStatus`. Constant `MAX_ATTEMPTS` = 3. Files: `sync/base.json`, `sync/state.json`. Caller: `routes/sync.ts` (`syncRoutes`).
- `app/sync/github.ts`: GitHub access through the `gh` CLI; no token is stored. Exports `REPO_NAME` (`dotmip`), `parseAccounts`, `listAccounts`, `pickAccount`, `ghToken`, `gitHubAccount`, `ensureRepo`, `repoUrl`, `authEnv`. Caller: `engine.ts`.
- `app/sync/repo.ts`: the local clone, `REPO_DIR` = `MIP_HOME/sync/dotmip`. Exports `fetchRepo`, `readTree`, `writeTree`, `commitAndPush`. Caller: `engine.ts`.
- `app/sync/snapshot.ts`: this machine as a snapshot, and the reverse. Exports `readLocal`, `applySnapshot`. Caller: `engine.ts`.
- `app/sync/merge.ts`: the pure three-way merge (no database, no git). Exports `mergeSnapshots`, `countChanges`, `keyOf`, `PARTS` (16 parts), `emptySnapshot`, `isEmptySnapshot`, `snapshotFromSaved` (maps an old `chats` part to `agents`), `sameRecord`, `sortKeys`, `indexBy`, `unionMessages`, and the record and `Snapshot` types. Callers: `engine.ts`, `snapshot.ts`, `repo.ts`.
- GitHub accounts (`github.ts`):
  - `listAccounts` runs `gh auth status --hostname github.com` and parses its text. It never rejects; it returns `error` (gh missing, or no account signed in).
  - `pickAccount(accounts, chosen)`: the chosen login while gh still has it, else the active account, else the first.
  - `ghToken(login)`: `gh auth token --hostname github.com --user <login>`. A failure is 409.
  - `gitHubAccount(login)`: checks the token with `GET /user`. A failure is 502.
  - `ensureRepo(token, login)`: `GET /repos/<login>/dotmip`. A public repo is 409. A missing one is created with `POST /user/repos` (`private: true`, `auto_init: true`). GitHub calls time out after 10 s (502).
  - `authEnv(token)`: git environment (`GIT_CONFIG_COUNT`) that sets an `Authorization: basic` header for `https://github.com/` only. The token is in no URL, argv, or config file.
- Storage:
  - `sync/state.json`: `{account, lastSync}`. Read once when `engine.ts` loads. Written by `chooseAccount` and at the end of each background run. No mode is set.
  - `sync/base.json`: `{repo, snapshot}`, the merge base. Written at the end of each run that was not rejected (after the push, or when there was nothing to push). No mode is set (see Gotchas).
  - `sync/dotmip/`: the clone. Local edits there are overwritten by the next sync.
  - Repo layout: one JSON file per record, named `encodeURIComponent(key) + ".json"`, in `personas/`, `bots/`, `notes/`, `agents/`, `mcp/`, `mail/`, `slack-app/`, `slack/`, `pi-credentials/`, `pi-models/`, `pi-files/`, `mail-cache/`, `slack-cache/`, `spending/`. `rooms.json` and `room.json` are single files. `README.md` is rewritten on each run. `chats/` (the old name of `agents/`) is read when `agents/` is missing and is removed on the next write.
- Phases (`syncWith`):
  1. `readLocal()` once, as the base of the `pulled` count.
  2. Per attempt, at most `MAX_ATTEMPTS`: `fetchRepo` (clones again when the URL differs from the clone's `origin`; otherwise fetches and checks out `origin/main`; an empty remote gets `HEAD` pointed at `main`), `readTree()` (remote), `readBase(repo)`, `readLocal()`.
  3. Refusal: 409 when the local snapshot is empty and the base is not.
  4. `mergeSnapshots(base, local, remote)`, then `applySnapshot(local, merged)`, then `readLocal()` again as `final`.
  5. When `mcp` changed, `startMcpServers()` runs without being awaited. When Pi files changed, `reloadPiConfig()` runs.
  6. `writeTree(final)`, then `commitAndPush` (author `mip <mip@localhost>`, message `Sync from mip <ISO time>`).
  7. `rejected` (GitHub's `main` moved): the next attempt. After the last rejected attempt: 409 `GitHub changed during the sync. Sync again.`. Otherwise `writeBase(final, repo)` and the run is returned: `pulled` (changes from the start to `final`), `pushed` (changes from remote to `final`), `notes`, and `message` (`Already in sync.` or `Pulled N, pushed M[, K merged].`).
- Merge base: `readBase` returns the saved snapshot only when its `repo` equals the current `<login>/dotmip`. Otherwise it returns the empty snapshot, so switching accounts never reads the old repo's records as deletes.
- Merge rules, per record (`mergeKind` in `merge.ts`):
  - Same on both sides: that value. Changed on one side only (against the base): that side's value. Deleted on one side and unchanged on the other: deleted.
  - Edited on one side and deleted on the other: the edit is kept, with a note.
  - Edited on both sides, by kind:
    - Newer `updatedAt` wins; a tie goes to GitHub: persona, bot, note, room, Pi credential, Pi model catalog.
    - Agent: newer settings; messages from both sides are kept and never removed.
    - Room messages: both sides kept; never edited or removed. A message of a removed room goes with the room.
    - Slack cache: newer `at` wins, no note. Mail cache: GitHub's copy, no note.
    - No change time, so GitHub's copy wins, with a note: mcp, mail, slack-app, slack, Pi config file, spending entry.
- Keys (`keyOf`): persona, agent, room by `id`; bot and note by lowercased `name` or `title`; message by `createdAt:role:` + the first 12 hex characters of the SHA-1 of its text; room message adds the room, kind, and author; mcp by `name`; mail and Slack account by `id`; Slack app by `"app"`; Pi credential and model by `providerId`; Pi file by `name`; mail cache by `accountId`; Slack cache by `key`; spending by `id`.
- Refusals and errors:

  | Condition | Result |
  | --- | --- |
  | `startSync` while a run is active | 409 `A sync is already running.` |
  | `chooseAccount` while a run is active | 409 |
  | `chooseAccount` to a login gh does not have | 400 |
  | `startSync` with no gh account | 409 (sign in with `gh auth login`) |
  | `gitHubAccount`: GitHub refuses the token | 502 |
  | `ensureRepo`: `dotmip` on GitHub is public | 409 |
  | `mcp.json`, `mail.json`, or `slack.json` has a problem (or is not JSON) | 409 from `readLocal`; nothing is pushed |
  | local snapshot empty while the base is not | 409 `This database is empty, but the last sync had data.` |
  | a merged MCP, mail, or Slack record will not load | 409 from `applyMcp`, `applyMail`, or `applySlack`; that file is unchanged |
  | three rejected pushes | 409 `GitHub changed during the sync. Sync again.` |
  | invalid JSON in a repo file or in `base.json` | plain `Error`, reported as the run's `message` |

- Concurrency: one run at a time. `running` is set before the first `await` in `startSync` and cleared in `runInBackground`'s `finally`. `syncWith` has no guard of its own. When two machines push, the second push is rejected and merges again, up to `MAX_ATTEMPTS`.
- Sync carries: the database parts (`storage/sync.ts`), `mcp.json`, `mail.json`, `slack.json` (app and accounts), Pi credentials, catalogs, and config files, the mail and Slack caches, and spending. Not synced: skills, live mail and Slack connections, pending Slack sign-ins, `base.json`, `state.json`.
- Gotchas:
  - Secrets: `sync/base.json` holds the whole synced snapshot in plain text, including mail app passwords, Slack tokens and client secret, MCP tokens, and Pi credentials. `base.json`, `state.json`, and the clone's files are written with no mode, so the umask decides. `mcp.json`, `mail.json`, and `slack.json` are chmod 600 on every write.
  - `applySnapshot` writes files in this order: mcp, mail, slack, Pi, caches, database. A refusal part-way leaves the earlier files written and pushes nothing. The next sync merges again.
  - `state.json` is parsed at module load with no `try`. A corrupt file stops the server from starting. `base.json` is parsed on each sync with no `try`: a corrupt file fails every sync, with the error in `lastSync.message`, until it is removed. With it removed, the merge runs against an empty base.
- Tests (run after a build; `merge.test.mjs` imports `dist`): `github.test.mjs` (gh's text parsing, the chosen then active then first account, a login gh cannot verify is skipped); `merge.test.mjs` (each merge rule and its note per part, caches, agent and room messages, the old `chats` snapshot); `sync.test.mjs` (two machines, each its own `MIP_HOME`, and local bare repos through real git: first and repeat syncs, newer edit wins, deletes travel, account switch, repo layout, the `chats/` layout, agent messages and questions, MCP servers, a broken `mcp.json` refused with nothing deleted on GitHub, Pi files).

Its credential and model stores are passed in, typed by `@earendil-works/pi-ai`'s `CredentialStore` and `ModelsStore`. `app/providers.ts` passes `sessionDir` (`MIP_HOME/sessions/pi`), `agentDir` (`MIP_HOME/data/pi`), and `DbCredentialStore` and `DbModelsStore` (`app/pi/store.ts`).   - `targets()`: every Pi provider except `anthropic` (`HIDDEN_PROVIDERS`), with method `subscription` (OAuth) and/or `api_key`. `startSignIn` runs `runtime.login` in the background. `answerSignIn` resolves the pending `ask`. `signOut`: `runtime.logout`.
  - `models()`: the default entry (empty id) first, then one `provider/model` entry per available model. `allowModelNetwork: false`.
  - `run`: the session's `cwd` is `process.cwd()`, not the workspace. Context files and skills are off (`noContextFiles`, `noSkills`). Pi's built-in tools are off (`noTools: "builtin"`). App tools are custom tools through `toPiTool`; a `ToolResult` with `isError` is thrown, so Pi reports the call as failed. Events: `message_update` text deltas, `tool_execution_start` and `_end`, and `agent_end` (an `error` only when the last assistant message failed and no retry follows).
  - `reloadConfig()` drops the cached runtime, so the next call reads `models.json` again. `reloadPiConfig` (`app/providers.ts`) calls it when a sync changes `settings.json` or `models.json` (`app/sync/engine.ts`).
  - Callers: `app/runs.ts` and `app/room/room.ts` (`run`); `app/providers.ts` (the rest).

## storage/
- `db.ts`: `db`, the one `DatabaseSync` on `MIP_HOME/data/mip.db` (mode 0600), and `Row`. Importing it runs `ensureMipDirs()`, opens the file, creates every table (`CREATE TABLE IF NOT EXISTS`), then runs the migrations. Tables and columns: `data-model.md`.
  - Migrations: `sessions` to `agents` and `session_id` to `agent_id` (old databases). Drops `skill_enablements` and `bot_skill_enablements`. Adds each later column only when `hasColumn` finds it missing. Backfills `updated_at`, `meta_updated_at`, and each bot's `color`. Moves room messages with no room id into `main`. When `rooms` is empty, creates room `main` with every bot.
  - Startup recovery: `runs` with status `running` become `error`; `repos` with status `cloning` become `error` with "interrupted by a server restart".
  - Tests (after a build, against `dist/backend`, with a temporary `MIP_HOME`): `db.test.mjs` (an old database upgrades with its rows), `agent-ask.test.mjs` (questions and the bot switch, through sync).
- `paths.ts`: path constants and `ensureMipDirs()`. Constants: `MIP_HOME` (env `MIP_HOME`, default `~/.mip`), `DATA_DIR`, `DEVICE_ID_FILE`, `MCP_CONFIG_FILE`, `MAIL_CONFIG_FILE`, `MAIL_CACHE_FILE`, `SLACK_CONFIG_FILE`, `SLACK_CACHE_FILE`, `SESSIONS_DIR`, `REPOS_DIR`, `SYNC_DIR`, `SKILLS_DIR`, `PI_AGENT_DIR`. `ensureMipDirs()` creates `DATA_DIR`, `REPOS_DIR`, `PI_AGENT_DIR`, `sessions/claude`, and `sessions/pi`. What each folder and file holds: `data-model.md`, "Files outside SQLite".
- `agents.ts`: tables `agents` and `messages`. Types `Agent`, `ToolCall`, `Ask`, `Message`, `NewMessage`. Functions: `insertAgent` (new agents are open to bots), `listAgents`, `getAgent`, `countAgentsWithPersona`, `listMessages` (by `created_at`, then `id`), `addMessage`, `renameAgent`, `setAgentSettings`, `setAgentOpenToBots`, `saveProviderSession`, `deleteAgent`.
  - `renameAgent`, `setAgentSettings`, and `setAgentOpenToBots` set `meta_updated_at`. `saveProviderSession` sets `updated_at` and the provider's session id. Sync does not carry the session id.
  - `deleteAgent` removes `run_events`, `runs`, `messages`, and `agents` in one transaction. Provider files and the workspace are not touched.
- `runs.ts`: tables `runs` and `run_events`. `createRun` (status `running`), `getRun`, `activeRunForAgent`, `setRunStatus` (`done` or `error`), `appendRunEvent` (the caller gives `seq`), `listRunEvents` (events with `seq` greater than the given one). Not synced.
- `notes.ts`: tables `notes`, `notes_fts` (FTS5), `note_links`, `note_tags`. Type `Note`. Functions: `getNoteByTitle`, `saveNote` (one transaction: row, search entry, links, tags; takes `updatedAt`), `listNotes`, `deleteNote` (one transaction; links from other notes to its title stay), `searchNotes` (`MATCH`, best rank first, with a body snippet), `linksFrom`, `linksTo`, `allLinks`, `tagsOf`. A link's target note need not exist.
- `personas.ts`: table `personas`. Type `Persona`. Functions: `listPersonas`, `getPersona`, `insertPersona`, `updatePersona`, `setDefaultPersona` (sets the one default and clears the rest), `deletePersona`. `is_default` is local and is not synced.
- `bots.ts`: table `bots`. Type `Bot`. Functions: `listBots` (by name, ignoring case), `getBot`, `getBotByName`, `insertBot`, `updateBot`, `deleteBot`. `deleteBot` removes the bot's `room_bots` rows and leaves `rooms.master_bot_id` as it was; `app/room/rooms.ts` clears a dangling master on the room's next edit.
- `bot-colors.ts`: `BOT_COLORS` (`frost`, `orange`, `violet`, `green`, `yellow`, `red`, `teal`, `blue`; a new bot takes the first one no bot has), `BotColor`, `isBotColor`. Not a table. Used by `bots.ts`, the `color` migration in `db.ts`, and `app/bots.ts`.
- `room.ts`: table `room_messages`. Type `RoomMessage` (`kind`: `user`, `bot`, `agent`, `system`). Functions: `addRoomMessage` (returns the saved row), `roomMessagesAfter(roomId, afterId, limit)` (oldest first; `afterId` 0 gives the newest `limit`), `searchRoomMessages` (every word must appear; `LIKE` with `\` escapes; newest first). Calls are stored here. Sync does not carry them.
- `rooms.ts`: tables `rooms` and `room_bots`. `MAIN_ROOM_ID` (`"main"`), type `Room` (`botIds`, `masterBotId`, `collapseOthers`). Functions: `listRooms`, `getRoom`, `getRoomByName` (ignores case), `roomCount`, `insertRoom`, `updateRoom` (sets `updated_at`), `deleteRoom` (also its `room_messages`).

- `spending.ts`: table `spending_entries`. Type `SpendingEntry` (`kind`: `income` or `expense`). Functions: `listSpendingEntries` (newest first), `getSpendingEntry`, `insertSpendingEntry` (`INSERT OR REPLACE` by id, so it also edits), `removeSpendingEntry`. Synced as the `spending` part (`app/sync/snapshot.ts`). The table has no change-time column.
- `pi.ts`: tables `pi_credentials` (`credential` as JSON), `pi_models` (`entry` as JSON), and `pi_state` (key and value). Files: `settings.json` and `models.json` in `PI_AGENT_DIR`. Types `PiCredentialRow`, `PiModelRow`, `PiConfigFile`. `PI_CONFIG_FILES` is the list of file names the app writes there. Functions: `readPiCredentialRows`, `readPiCredentialRow`, `writePiCredentialRow`, `removePiCredentialRow`, `readPiModelRows`, `readPiModelRow`, `writePiModelRow`, `removePiModelRow`, `readPiState`, `writePiState`, `readPiConfigFile`, `writePiConfigFile`, `removePiConfigFile`. Writes keep the `updatedAt` they are given. Callers: `app/pi/store.ts`, `app/sync/snapshot.ts`, `app/sync/repo.ts`.
- `sync.ts`: no table of its own. The row layer for GitHub sync, called only by `app/sync/snapshot.ts`. Row types: `PersonaRow`, `BotRow`, `NoteRow`, `AgentRow`, `MessageRow`, `RoomRow`, `RoomMessageRow`. Read and write functions per kind: `readPersonaRows` and `writePersonaRow`, `readBotRows` and `writeBotRow`, `readNoteRows` and `writeNoteRow`, `readAgentRows` and `writeAgentRow`, `readMessageRows` and `insertMessageRow`, `readRoomRows` and `writeRoomRow`, `readRoomMessageRows` and `insertRoomMessageRow`. Removals: `removePersonaRow`, `removeBotRow`, `removeNoteRow`, `removeAgentRow`, `removeRoomRow`.
  - A removal returns false where the database keeps the row: the default persona, a persona an agent uses, an agent with a running run, and the last room.
  - Matching: bots by name (ignoring case), notes by title, rooms by id, and room members and master by bot name. A room name that another room has gets ` (2)`, ` (3)`, and so on.
  - Messages are only inserted (`insertMessageRow`, `insertRoomMessageRow`). They leave with their agent or room. Rows carry no `calls`, no `provider_session_id`, and no `is_default`.
  - `writeAgentRow` keeps the larger of the two `updated_at` values.
  - Test: `agent-ask.test.mjs`.

## Rules across the backend
- Import direction: `http/` imports `app/` (and one type from `adapters/contract.ts`). `app/` imports `storage/` and `adapters/`. `storage/` imports `node:`, types from `@earendil-works/pi-ai` (`storage/pi.ts`), and its own files. `adapters/` imports `node:`, the Pi packages, `typebox`, and its own files. Why: the database and the providers can change without touching the layers above.
- Only `storage/` opens SQLite (`db`). `app/` calls storage functions. Why: one connection, and the row mapping lives in one place.
- Storage maps rows to its own types (`toAgent`, `toBot`, and so on) and parses its JSON columns there. Why: callers never see column names or JSON text.
- Storage checks no input. Input checks live in `app/` (for example `saveSpendingEntry`). Why: every caller gets the same checks.
- Route handlers parse input only. Each `http/routes/*.ts` handler reads the body with `readJson`, picks its fields, calls the `app/` functions it needs, and returns the result as a `Reply` (`ok`, `created`, `accepted`, `ack`). Why: rules stay in `app/`, where they run without HTTP. Exception: `GET /api/memory/:title` in `routes/memory.ts` throws its own 404.
- Client mistakes throw `AppError(status, message)`: 400 for bad input, 404 for a missing record, 409 for a conflict (a busy room, a running agent, a config file with a bad entry at sync), 502 for a failed call to Slack, GitHub, a mail server, or an MCP sign-in. Routes never catch. `http/server.ts` replies with the error's status and `{ error: message }`. Any other error is a 500 with the same body. Why: the caller needs a status it can act on.
- Providers are reached only through `app/providers.ts` (`findProvider`, `listProviders`, `signIn`, `answerSignIn`, `signOut`). Only that file constructs providers. Why: one list decides which providers exist and where each keeps its files.
- A run's events are saved as they arrive (`run_events`, `seq` per run). Why: a run goes on after its page closes, and a page can read from its last `seq`.
- A run can call only the tools it was started with: `AGENT_TOOLS` for an agent, `BOT_TOOLS` for a bot (`app/tools/index.ts`). The tool endpoint `POST /mcp` (`http/mcp.ts`) takes the run from the bearer token, and `tools/list` and `tools/call` use only that list. Why: a token opens one run's tools, folder, and room, and nothing else.
- Every write to a synced row sets its change time: `updated_at` (personas, bots, notes, rooms, Pi rows) or `meta_updated_at` (agent title and settings). Rows written from GitHub keep the time they came with, so an equal copy stays equal. Why: GitHub sync merges by change time (`app/sync/merge.ts`). Exception: `spending_entries` has only `created_at`, and an edit keeps it, so sync keeps GitHub's copy of two edits. Full list: `data-model.md`.
- Rows that must agree change in one transaction (`BEGIN`, `COMMIT`, `ROLLBACK`): `saveNote`, `deleteNote`, `deleteAgent`. Why: a note's search entry, links, and tags follow its body. Gap: `insertRoom`, `updateRoom`, `deleteRoom`, `deleteBot`, `removeBotRow`, and `writeRoomRow` run several statements with no transaction, so a failure midway leaves them partly changed.
- At startup, `running` runs and `cloning` repos become `error` (`db.ts`). Why: the process that would finish them died with the server.
- Sync stops before it writes when `mcp.json`, `mail.json`, or `slack.json` has an entry that does not load (409, `app/sync/snapshot.ts`). Why: a server left out of the file would be deleted on GitHub.
- No provider or token is logged. The backend's `console` calls are the startup lines in `http/server.ts` (including the Pi auth import), and the errors `app/runs.ts` and `app/room/room.ts` log when a save or a room conversation fails. The adapters log nothing. Gotcha: the run token is an argument of the `claude` process (`--mcp-config`), so local users can see it in the process list.
